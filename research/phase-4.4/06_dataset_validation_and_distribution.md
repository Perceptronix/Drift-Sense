## 1. Dataset Validation

### 1.1 Validation Levels

| Level | Scope | Method | Timing |
|---|---|---|---|
| **L1: File completeness** | Directory structure | Check expected files against manifest | After generation |
| **L2: Metadata consistency** | Cross-field agreement | Parameter cross-references | After generation |
| **L3: Ground truth consistency** | GT ↔ image agreement | Edge/height/image coordinate check | After generation |
| **L4: Version compatibility** | File versions match | Schema version check | Before use |
| **L5: Reproducibility** | Determinism | Config + seed → expected hash | CI / audit |

### 1.2 File Completeness (L1)

| Check | Method | Failure |
|---|---|---|
| All image files exist | Scan `images/*.tiff`, compare to manifest | Error: missing image |
| All GT files exist | Scan `ground_truth/*.json`, compare to manifest | Error: missing GT |
| All metadata files exist | Scan `metadata/*.json`, compare to manifest | Error: missing metadata |
| No orphan files | Manifest references match disk exactly | Warning: extra files |
| Split files exist | `splits/train.txt`, `val.txt`, `test.txt` | Warning: missing splits |

### 1.3 Metadata Consistency (L2)

| Check | Cross-Reference |
|---|---|
| Config file matches metadata | `structure_type`, `cd_nm`, `height_nm` must agree |
| Seed chain consistent | `master_seed → structure_seed → image_seed` must follow derivation rule |
| Physics parameters agree | `beam_energy_keV` same in config and metadata |
| Dimensions consistent | Image dimensions in config match actual image file dimensions |

### 1.4 Ground Truth Consistency (L3)

| Check | Method |
|---|---|
| Edge positions plausible | Edges from GT must be near edges computed directly from height field |
| CD values match height field | CD_top measured from height field must match GT CD_top within tolerance |
| Material segmentation matches material map | Material IDs identical between GT and material map |
| LER 3σ reported matches measured | GT LER = standard deviation measured from edge contour |

### 1.5 Version Compatibility (L4)

| Check | Rule |
|---|---|
| Schema version | All files in dataset share the same schema version |
| Application version | All samples generated by same application version (or documented upgrade) |
| Material library hash | All samples use same material library version |

### 1.6 Reproducibility (L5)

| Check | Method | Tolerance |
|---|---|---|
| Deterministic regeneration | Re-run with same config + seed; verify SHA-256 of image | Exact match |
| Config snapshot fidelity | Snapshot loaded as config → same structure parameters | Exact match |
| Seed derivation | Re-derive seed chain and compare to recorded | Exact match |

## 2. Dataset Statistics

After validation, aggregate statistics are computed:

| Statistic | Computation | Purpose |
|---|---|---|
| Per-structure-type counts | Count samples by structure type | Class balance |
| Parameter range coverage | Min/max/mean/std of each numeric parameter | Distribution quality |
| Image intensity statistics | Mean, std, min, max, histogram across dataset | Brightness normalization reference |
| Failure rate | Fraction of failed samples | Quality indicator |
| LER/LWR distribution | Histogram of measured LER across samples | Variability quality |
| CD accuracy | (Measured CD − configured CD) distribution | Process model fidelity |

## 3. Dataset Distribution

### 3.1 Packaging Options

| Method | Pros | Cons | Verdict |
|---|---|---|---|
| **Directory tree + archive** | Simple; universal access; no special tools | Multiple files; transfer as .zip/.tar | **Recommended** |
| HDF5 single file | One file; self-describing; compression | Requires HDF5 tools; opaque diff | Not for primary distribution |
| Database (SQLite) | Queryable; ACID | Not standard for ML datasets | Rejected |
| Cloud bucket (S3/GCS) | Scalable; CDN access | Requires cloud infrastructure | Secondary distribution |

**Engineering Decision:** Datasets are distributed as a compressed archive (.tar.gz or .zip) of the canonical directory tree. One dataset = one archive.

### 3.2 Compression

| Component | Compression | Typical Ratio |
|---|---|---|
| Images (TIFF LZW) | Already compressed in-file | ~2:1 over raw |
| Ground truth (JSON) | gzip (`.json.gz` optional) | ~5:1 |
| Metadata (JSON) | gzip (`.json.gz` optional) | ~5:1 |
| Height field (`.npy`) | NumPy .npy (uncompressed) or .npz (compressed) | ~2:1 (npz) |
| Entire dataset archive | `.tar.gz` (gzip level 6) | ~2:1 |

### 3.3 Integrity Verification

Each distributed dataset includes:

| File | Content | Purpose |
|---|---|---|
| `SHA256SUMS` | SHA-256 of every file in the dataset | File integrity verification |
| `dataset.tar.gz` | Compressed archive | Distribution |
| `dataset.tar.gz.sha256` | SHA-256 of the archive | Download integrity |
| `dataset.tar.gz.sig` | GPG signature (optional) | Authenticity verification |

### 3.4 Licensing

| Element | Recommendation |
|---|---|
| **License** | CC BY 4.0 (Creative Commons Attribution 4.0) |
| **Why** | Permissive for both academic and commercial use; requires attribution |
| **Attribution** | "Generated with SEMICON-2026 Synthetic SEM Simulator" |
| **Citation guidance** | Provided in README.md as BibTeX entry |

## 4. Dataset README Template

```
# {Dataset Name}

## Description
{Sentence describing the dataset and its purpose}

## Contents
- {N} SEM images (1024×1024, 16-bit TIFF)
- {N} ground truth annotation files (JSON)
- {N} configuration snapshots and metadata records (JSON)
- Train/validation/test splits

## Dataset Version: v{major}.{minor}.{patch}
- Generation date: {date}
- Generator version: {version}
- Schema version: {schema_version}

## Structure Types
- {type_1}: {count} samples
- {type_2}: {count} samples

## Parameters Varied
- {parameter_1}: [{min}, {max}]
- {parameter_2}: [{min}, {max}]

## File Format
- Images: 16-bit grayscale TIFF (LZW compression)
- Annotations: JSON (UTF-8)
- Height fields: NumPy .npy (float64)

## License
CC BY 4.0

## Citation
{BibTeX entry}

## Integrity
SHA256SUMS file included. Verify with: sha256sum -c SHA256SUMS
```
